## 2. Принцип работы

Инъекция выполняется в четыре этапа:

1. **OpenProcess** – получение дескриптора целевого процесса с правами `PROCESS_CREATE_THREAD | PROCESS_VM_WRITE | PROCESS_VM_OPERATION`.
2. **VirtualAllocEx** – выделение памяти в адресном пространстве жертвы под строку с полным путём к DLL.
3. **WriteProcessMemory** – запись пути в выделенную область.
4. **CreateRemoteThread** – создание удалённого потока, стартовой точкой которого является `LoadLibraryA`, а параметром – адрес записанной строки. Это заставляет целевой процесс загрузить нашу DLL.

После загрузки срабатывает `DllMain` с причиной `DLL_PROCESS_ATTACH`, и выполняется наш код (в данном случае – показ `MessageBox` с именем процесса). Это подтверждает успешное внедрение.

## 4. Описание компонентов

### 4.1. VirusDLL (VirusDLL.cpp → VirusDLL.dll)

Внедряемая библиотека. При загрузке в чужой процесс через `DllMain` вызывает `AttackProcess()`, которая:
- получает имя текущего процесса через `GetModuleBaseNameA`;
- выводит `MessageBox` с текстом `"BOOM!"` и именем процесса в заголовке.

Это служит индикатором успешной инъекции.

### 4.2. DllInjectorAsProcess (DllInjectorAsProcess.cpp → Injector.exe)

Консольное приложение, выполняющее все четыре шага инъекции для заданного PID:

```
Injector.exe <PID>
```

Путь к `VirusDLL.dll` жёстко задан как `C:\Temp\VirusDLL.dll` (при необходимости измените в исходнике). При успехе выводит `"DLL injected successfully."`.

### 4.3. DllInjectorAsDll (DllInjectorAsDll.cpp → DllInjectorAsDll.dll)

Та же логика инжекции, но оформленная как DLL с экспортируемой функцией `HelperFunc`. Позволяет запускать инжектор через системную утилиту `Rundll32.exe` без отдельного EXE-файла:

```
Rundll32.exe <путь>\DllInjectorAsDll.dll,HelperFunc <PID>
```

Экспорт функции обеспечивается с помощью `__declspec(dllexport)` и `extern "C"`. Для 32-битной сборки может потребоваться `.def`-файл для точного имени.

### 4.4. ProtectedProcess (ProtectedProcess.cpp → BlockDLL.exe)

Реализует защиту с использованием политики `PROCESS_CREATION_MITIGATION_POLICY_BLOCK_NON_MICROSOFT_BINARIES_ALWAYS_ON`.

**Алгоритм защиты:**
1. Процесс запускается без аргументов.
2. Он определяет свой путь и перезапускает себя с маркерным аргументом (например, `"xakep"`), используя `CreateProcessA` с расширенными атрибутами.
3. В атрибуты через `InitializeProcThreadAttributeList` и `UpdateProcThreadAttribute` записывается политика блокировки.
4. Дочерний процесс, видя маркер, переходит к основной работе (бесконечный цикл с выводом счётчика) и становится защищённым.

При попытке внедрения `VirusDLL.dll` в такой процесс Windows отклоняет загрузку на уровне ядра (`NtMapViewOfSection`), и `CreateRemoteThread` возвращает ошибку (например, `ERROR_ACCESS_DISABLED_BY_POLICY`). Окно `BOOM!` не появляется.

### 4.5. web-site.html

Фишинговая страница, демонстрирующая запуск инжектора из браузера через ActiveX:
- JavaScript создаёт объект `WScript.Shell` и выполняет команду `Rundll32.exe` с `DllInjectorAsDll.dll` и переданным PID.
- Работает **только** в Internet Explorer (из-за поддержки ActiveX). В современных браузерах этот сценарий заблокирован.

## 5. Сборка (опционально)

Готовые бинарники уже находятся в папке `src/`. Если требуется пересобрать:

**Требования:** MinGW-w64 (для кросс-компиляции в Linux) или Visual Studio (в Windows).

**Пример сборки с MinGW (Linux):**
```bash
# VirusDLL.dll (64-bit)
x86_64-w64-mingw32-g++ -shared -o VirusDLL.dll VirusDLL.cpp -lpsapi -static-libgcc -static-libstdc++

# Injector.exe
x86_64-w64-mingw32-g++ -o Injector.exe DllInjectorAsProcess.cpp -static-libgcc -static-libstdc++

# DllInjectorAsDll.dll
x86_64-w64-mingw32-g++ -shared -o DllInjectorAsDll.dll DllInjectorAsDll.cpp -static-libgcc -static-libstdc++

# BlockDLL.exe (ProtectedProcess)
x86_64-w64-mingw32-g++ -o BlockDLL.exe ProtectedProcess.cpp -lpsapi -static-libgcc -static-libstdc++
```

Для 32-битной сборки используйте префикс `i686-w64-mingw32-`.

## 6. Запуск и тестирование

Все операции выполняются в Windows с правами **администратора**. Поместите все файлы из `src/` в одну папку, например `C:\Temp\`. Убедитесь, что в коде инжекторов путь к `VirusDLL.dll` указан как `C:\\Temp\\VirusDLL.dll` (или измените его).

### 6.1. Проверка инжекции в обычный процесс
1. Запустите любой процесс, например `notepad.exe`.
2. Узнайте его PID через диспетчер задач или `tasklist`.
3. Выполните команду:
   ```
   Injector.exe <PID>
   ```
   или через Rundll32:
   ```
   Rundll32.exe C:\Temp\DllInjectorAsDll.dll,HelperFunc <PID>
   ```
4. В окне Блокнота появится окно `BOOM!` – инжекция прошла успешно.

### 6.2. Тестирование защиты
1. Запустите `BlockDLL.exe` – откроется консоль с сообщением о создании защищённого процесса и его PID.
2. Во втором окне (дочернем) начнётся вывод счётчика – это защищённый процесс.
3. Попытайтесь внедрить `VirusDLL.dll` с помощью `Injector.exe <PID_защищённого_процесса>`.
4. Вместо `BOOM!` вы увидите ошибку (например, `CreateRemoteThread failed (error 1260)` или `Bad Images`). Защита сработала – DLL не была загружена.

### 6.3. Запуск через веб-страницу
1. Откройте `web-site.html` в **Internet Explorer** (не Edge).
2. Разрешите выполнение ActiveX-скриптов (настройте зону безопасности или разрешите блокированное содержимое).
3. В скрипте замените `12345` на актуальный PID целевого процесса (например, notepad.exe).
4. Нажмите кнопку – инжектор запустится, и появится `BOOM!`.

## 7. Результаты

- **Обычная инжекция** – успешно выполняется, DLL загружается в целевой процесс.
- **Инжекция в защищённый процесс** – блокируется политикой `PROCESS_CREATION_MITIGATION_POLICY_BLOCK_NON_MICROSOFT_BINARIES_ALWAYS_ON`. DLL не загружается, `MessageBox` не появляется.

Таким образом, механизм `UpdateProcThreadAttribute` является эффективной защитой от классической DLL-инъекции, так как запрещает загрузку любых неподписанных Microsoft DLL на уровне ядра.
